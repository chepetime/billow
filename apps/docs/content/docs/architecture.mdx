## Monorepo layout

```text
apps/
  web/          Next.js App Router application (the product)
  docs/         This documentation site (Fumadocs)
packages/
  db/           @billow/db — Prisma schema, migrations, seed, client
  auth/         @billow/auth — BetterAuth config, session, registration, recovery-key
  crypto/       @billow/crypto — data-key hierarchy and field-encryption primitives
  email/        @billow/email — Resend integration and transactional templates
  ui/           @billow/ui — shared React primitives
  shadcn/       @billow/shadcn — shadcn-derived components
```

pnpm workspaces define the members; Turborepo orchestrates `build`, `test:run`,
and the `db:*` tasks. Lint is not a Turborepo task: `pnpm lint` runs Biome
(`biome check .`) once over the whole repo rather than per package.

## Request flow

```text
Browser
  → Umbrel app_proxy            (only in production)
  → Next.js (apps/web)
      proxy.ts                  optimistic redirect for /dashboard, /settings
      Server Component          requireSession() / getSession()
      → @billow/db getPrisma()  → Postgres
```

Route groups carry the access rules:

- `app/(auth)/*` — public, redirects **away** when already signed in
- `app/(app)/*` — the layout calls `requireSession()`; this is the real gate
- `app/api/v1/*` — public REST surface, authenticated by API key or session

`proxy.ts` (Next's replacement for `middleware.ts`) is a fast-path only. It
checks for a session **cookie**, not a valid session, so the server layout
remains the source of truth.

## Auth model

BetterAuth with the Prisma adapter, plus three plugins:

- `username` — a username can be used to sign in instead of an email
- `twoFactor` — TOTP enrolment with single-use backup codes
- `apiKey` (`@better-auth/api-key`) — personal access tokens

Registration is **first-user-only** by default: a `databaseHooks.user.create.before`
guard rejects sign-ups once an account exists, so the rule holds no matter which
UI or endpoint is used.

### Origins, not domains

`BETTER_AUTH_URL` is deliberately **not** pinned. `auth-env.ts` falls back to an
in-container URL and `trustedOrigins` trusts the request's `Origin` header, so
sign-in works through `umbrel.local`, Tailscale, Cloudflare, or a raw IP.

<Callout type="warn">
This weakens BetterAuth's cross-site (CSRF) check on purpose. It is an accepted
trade for a single-user app behind network auth, and should be tightened once
the app is reached over a stable HTTPS hostname.
</Callout>

### Password-reset email links and header trust

The same "no pinned domain" tradeoff shows up in password-reset emails.
`packages/email/src/public-url.ts` builds the link's origin from the request's
`Host`/`X-Forwarded-Host` headers when no public URL is configured — the same
headers `trustedOrigins` above reads. Unlike the CSRF case, no browser
same-origin rule protects this: whoever sends the password-reset request
controls those headers on their own request, so an unauthenticated attacker
who submits a reset request for someone else's address with a forged
`X-Forwarded-Host` can make the emailed link point at a domain they control,
handing them the token when the victim clicks it.

Two settings close this:

- **Settings → Administration → Email → Public URL** (`emailSettings.publicUrl`)
  pins one canonical origin; once set, request headers are never consulted.
- **`BILLOW_TRUSTED_ORIGINS`** (the same env var `trustedOrigins` reads) is
  checked as an allowlist when no public URL is set: a header-derived origin
  outside it is rejected rather than trusted, and the app refuses to send
  rather than mail out a link to an unverified host.

<Callout type="warn">
An install with **neither** set — the out-of-the-box LAN default — still
trusts the header-derived origin outright, because the app cannot otherwise
tell a genuine reverse-proxy header from a forged one, and refusing to send
always would break password reset on most installs. In practice this window
is narrow: password-reset email only sends once an administrator has
configured a provider on that same Settings page, one field away from also
setting the Public URL. Operators who expose the app directly (not solely
through Umbrel's `app_proxy`) should set one of the two above.
</Callout>

## Data access

`@billow/db` owns Prisma end to end and exports `getPrisma()`, a cached client
wrapped in a retry extension: connection-level failures (`P1001`, `P1002`,
`P1017`) are retried, while authentication failures (`P1000`) fail fast so real
misconfiguration surfaces immediately at `/health`.

Workspace data is scoped by `userId`; loaders in `lib/invoice-workspace.ts` take
the signed-in user and filter every query.
