## zod is the single source of truth

Schemas live in `apps/web/src/lib/schemas/` and drive three things at once:

1. runtime validation in `/api/v1/*` route handlers,
2. the OpenAPI document (via zod v4's `z.toJSONSchema()`),
3. client form validation through `@hookform/resolvers`.

Define a schema once and infer the type from it — never hand-write a matching
interface.

```ts
export const createApiKeySchema = z.object({
  name: z.string().min(1, "Name your key.").max(60),
});

export type CreateApiKeyInput = z.infer<typeof createApiKeySchema>;
```

## Forms

`react-hook-form` + `zodResolver`, with the shared `Field` component supplying
the label, error message, and `aria-describedby` wiring.

Keep two error channels apart: **field errors** come from the resolver and render
inside `Field`; **request errors** (the server said no) live in a `useState` and
render near the submit button.

## Server and client components

Server by default. Add `"use client"` only for interactivity. Anything touching
the database, `auth`, or secrets must also import `server-only`.

Per-request pages need `export const dynamic = "force-dynamic"`. This is not
optional cosmetics: `getSession()` swallows errors, which would otherwise let
Next statically prerender a page and hit the database at build time.

## Database changes

`prisma migrate dev` is interactive and fails in CI and agent shells. Use the
diff recipe instead:

```bash
set -a; . apps/web/.env; set +a
cd packages/db
DIR="prisma/migrations/$(date +%Y%m%d%H%M%S)_your_change"
mkdir -p "$DIR"
pnpm exec prisma migrate diff \
  --from-config-datasource --to-schema prisma/schema.prisma --script \
  > "$DIR/migration.sql"
pnpm exec prisma migrate deploy
```

<Callout type="warn">
When a BetterAuth plugin owns a table, its Prisma model must match the plugin's
field list **exactly**. Print the full list before writing the model — a
truncated read once missed `failedVerificationCount` and `lockedUntil` on
`twoFactor`, which failed only at runtime.
</Callout>

Never run `db:generate` through Turborepo's fan-out. Two concurrent
`prisma generate` runs write the same directory and race; the root scripts
target `@billow/db` directly.

## API routes

Every `/api/v1/*` handler follows the same shape:

```ts
export async function GET(request: Request) {
  const identity = await requireApiIdentity(request);
  if (identity instanceof NextResponse) return identity;
  // …
}

export async function POST(request: Request) {
  const identity = await requireApiIdentity(request, { mutating: true });
  if (identity instanceof NextResponse) return identity;
  // …
}
```

`requireApiIdentity` accepts an `x-api-key` header, an `Authorization: Bearer`
token, or a browser session. Errors use `{ error: string }` from
`lib/api/respond.ts`.

`{ mutating: true }` adds the same-origin (CSRF) check, and belongs on anything
that changes state. It applies only to cookie callers — a request carrying its
own API key is not something a hostile page can forge with the victim's
cookies — and it runs *after* credentials resolve, so an anonymous caller gets
401 rather than a 403 that sends them hunting for a permission problem.

<Callout type="warn">
Do not guard a read. Browsers send no `Origin` on a same-origin GET, so a
guarded read answers the app's own pages with 403 — a regression this repo has
already shipped once, on the vault.
</Callout>

Serial-id routes parse the path with `numericId` from
`lib/api/workspace-route.ts`, never `Number()`: `Number("0x10")` is 16 and
`Number("")` is 0, so the naive version gave two URLs for one row and turned an
empty segment into a lookup. `Invoice` is keyed by a UUID `publicId` and
validates with `invoicePublicIdSchema` instead.

## Workspace rules

A domain rule that both the UI and the API need lives in `lib/workspace/`,
takes the owner's `userId` as an argument, and returns a `WorkspaceResult` —
`{ ok: true, data }` or a refusal carrying a *reason*, never a sentence:

```ts
export async function updateClientCompany(
  userId: string,
  id: number,
  input: ClientCompanyInput,
): Promise<WorkspaceResult> { /* … */ }
```

Two thin callers map that reason outward, and neither one holds a rule:

- `lib/actions/*` supplies the session's user, revalidates the pages that
  changed, and turns the reason into form copy (`toActionResult`).
- `app/api/v1/*` supplies whoever the API key resolved to and turns the same
  reason into a status (`workspaceError` in `lib/api/workspace-route.ts`).

Both mappers switch exhaustively, so a new reason fails the build rather than
falling through to a 500.

<Callout>
The reason is the whole point. A rule that returns
*"That client is no longer in your workspace."* has picked a caller, and the
other one is left matching on English to choose between 404 and 409.
</Callout>

`ClientCompany` and `TaxPeriod` are the migrated entities. The older actions —
invoices, bank accounts, senders — still call `requireSession()` inline and are
not callable from a route yet; migrate one when it needs an endpoint, not
speculatively.

A rule also owns the destructive limits the database does not enforce.
`ClientCompany` gets `onDelete: Restrict` from `Invoice.clientCompanyId`, so
Postgres refuses to remove a client that was ever billed. `TaxPeriod` gets the
opposite — its documents are `onDelete: Cascade` and would be taken down with
it, orphaning the uploads they point at — so `deleteTaxPeriod` refuses while any
document is attached. Check the schema before exposing a `DELETE`; the answer
differs per model.

Ownership is the `userId` argument; encryption is `getWorkspacePrisma()`, which
reads the session itself and correctly hands an API-key caller the keyless
client. Keep the two separate — a rule that conflates them will either leak
another account's rows or refuse a write it should allow.

## Testing

Vitest, colocated as `*.test.ts`. Favour pure functions that can be tested
without a database — `canRegister`, `isEmailIdentifier`, and the zod schemas are
the model to follow.

## Style

- TypeScript strict. No `any`, and no `biome-ignore` to paper over a type error.
  A `biome-ignore` needs a reason after the colon; Biome fails the build on a
  suppression that no longer suppresses anything.
- Import shared UI from the workspace packages rather than redefining it.
- Comments explain **why**, not what.
